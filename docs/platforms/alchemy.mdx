The default `tdg init` template hosts agent state in Alchemy Domain and durable agent processes on Effect Cluster. `Thread` is the aggregate, `RunExecution` reacts to its facts, `ExecuteRun` is a standalone native workflow, and `ActorApi` exposes authorized commands and reads. Cloudflare hosting uses `DomainCloudflare.layerDurableObjects()`; the original Tardigrade journal, scheduler, watchdog, and raw actor Durable Objects are outside this template's call path.

## Create and run

```sh
tdg init assistant
cd assistant
cp .env.example .env
bun run dev
```

Start `bun run dev:runner` in another terminal. The Bun runner stores native Cluster messages and Workflow checkpoints in `TARDIGRADE_RUNNER_DB`. Its model provider, tool adapter and immutable result storage live in that process; the Worker hosts the Domain model and its policies. Set `TARDIGRADE_DOMAIN_URL` to the Worker’s `/internal` endpoint and `TARDIGRADE_RUNNER_URL` to the runner endpoint reachable from that Worker. Local defaults use the memory server on port 4242 and runner on port 4243. Cloudflare production requires reachable service URLs. Set `TARDIGRADE_ARTIFACT_DB` to a separate persistent SQLite file for complete spilled values. It is distinct from the Cluster message/checkpoint database; retain both files and keep them private.

Supply the model ID, provider credential, public bearer token and subject, and separate `WORKER_TO_RUNNER_TOKEN` and `RUNNER_TO_DOMAIN_TOKEN` credentials in `.env` before starting. There is no fallback model or account. Alchemy reads configuration during Worker initialization and owns its secret bindings. The reference adapter uses the native Effect AI OpenAI Responses provider with `current_time`, bounded HTTP tools `fetch_get` and `fetch_request`, durable text tools `write_text`, `read_text` and `list_texts`, native Code Mode through `execute`, and durable subagents through `delegate`. The HTTP tools preserve explicit methods, headers, text bodies, response status and bounded text; failed calls return their declared native errors to the model. `TARDIGRADE_FETCH_POLICY` overrides the exported complete `DEFAULT_FETCH_POLICY`, including request/response limits, text allowance and timeout. Returned results expose the accepted policy and truncation. A mutating HTTP request whose timeout or lost response leaves its effect uncertain blocks its run as unknown; readonly HTTP failures remain model-readable. An application supplies other models and tools by implementing the native `AgentExecution` external system.

`bun run cli --help` lists the commands derived from `ActorApi`. The public commands open a thread, request a run, approve a pending step, cancel a run, and reconcile an unknown result. Owner commands also approve, cancel, and reconcile code execution, cancel delegations, reply to child requests, and acknowledge their inbox. Admission of code and child work remains internal to trusted orchestration. Reads expose Thread, CodeExecution, Delegation, Workspace and SpillCatalog state and native event streams to their owner. `ThreadDirectory` routes root and child registration facts to the immutable owner. Its native paginated list and event stream expose thread IDs and names without copying the directory into a client store; names are labels and can repeat. Command IDs provide native transport idempotency; run IDs and monotonic step IDs enforce the model's additional invariants.

`bun run dev` runs Cloudflare locally through Alchemy. `bun run dev:memory` runs the state model in a Bun process with `Domain.InMemory`; its data ends with the process. Both state servers use the same separate Cluster runner. `bun run plan:cloudflare --stage prod` previews the stack and `bun run deploy:cloudflare --stage prod` deploys it. Keep the stack's `.alchemy` state between deployments. Generating this template does not transfer data from an existing Tardigrade deployment.

## Execution and recovery

Each thread has one active run. Native commands persist admission, step preparation, approval, dispatch, usage, and terminal outcomes. Every model/tool boundary has a native Activity result. The workflow reads snapshots through the private native Domain API and reuses recorded Activity results on replay. The policy schedules a native Domain expiry command and sends authenticated native Workflow control RPCs after approval, cancellation, failure, or an uncertain outcome. The Worker declares no agent sagas and registers no duplicate agent workflow engine.

A tool cannot dispatch before its prepared step is approved. The reference adapter advertises tools to the model with `disableToolCallResolution: true`; execution happens separately through the toolkit handler after the aggregate admits dispatch. Provider-executed tools are refused by the reference adapter. Application adapters are trusted code and must classify their tool effects accurately.

When dispatch was recorded but the external response was not, recovery records `unknown` and blocks another run. This includes a lost model response and uncertainty in nested Code or delegated work; the parent run also becomes unknown and cannot admit another run. A native reconciliation command requires an explicit outcome and evidence; it closes the affected run as failed before admitting new work. External execution does not have an exactly-once guarantee. Cancellation prevents subsequent dispatch and successful late settlement; it cannot undo an external mutation.

Turn and tool counters are precharged before dispatch. Reported token usage is accumulated once per settled step, and the model refuses subsequent work after exhaustion. The reference provider also receives the remaining token allowance as its output limit. Provider input tokens and lost responses can still incur charges beyond that output allowance; the limit is not a billing reservation. Deadlines use the native command clock and scheduled expiry.

The native event log retains execution evidence. Model context retains completed runs; failed and cancelled runs do not become the next run's context. A step whose output exceeds the message allowance retains its evidence in the event log and fails the run without enlarging the context beyond its configured limit.

## Boundaries

The native template uses a new Domain protocol. It does not promise compatibility with the original method HTTP protocol, arbitrary actor graph execution, deferred callbacks, or sandbox workspaces. The original atom DSL and explicit `agent` template retain their original state owners. The `quickstart` Counter and `rlm` templates use native Domain contracts. They are separate execution paths and are not a completed Domain migration.

The reference bearer adapter authenticates one explicitly configured subject. Applications with several users provide their own session middleware using `CurrentCaller`; identity must remain request-local. `Session` authenticates every public mutation and validates aggregate reads against the stored owner. `ReceiptOwnerGuard` checks the immutable owner before native command receipt lookup and again before returning the result, including an explicitly empty command ID. The second check denies a concurrent first-creation receipt belonging to another principal. Applications replacing the session adapter must also provide `ReceiptOwnerGuardLive`. Internal execution commands are excluded from `ActorApi`.

Child thread admission has a durable reservation and an irreversible fence bound to its parent, delegation, actor, and run. Root-thread commands cannot reopen or admit work into a child thread. Fencing preserves uncertain dispatched mutations for reconciliation. Native delegation workflows reserve and precharge admission, derive child limits from the accepted parent, open the bound child, and record its actual terminal receipt. Cancellation fences the child before recording absence or a terminal outcome, including after precharge. Transport failures suspend the cleanup workflow for native resume.

The Cluster package exports a native Workflow proxy with approval, interruption, resume, and poll controls. Every control requires `WORKER_TO_RUNNER_TOKEN` and checks that the owner, thread, and run produce the supplied workflow key. The private Domain HTTP endpoint checks `RUNNER_TO_DOMAIN_TOKEN` for all requests, including internal commands without session middleware and WebSocket upgrades. Owner identity travels in each RPC envelope and is decoded by the native session middleware; it is never a process-global principal.

Local integration tests run the production policy loop over two real HTTP servers with native Domain memory storage, Cluster, and SQLite: a requested run starts without a test calling its workflow directly, approval releases the tool, and cancellation prevents dispatch. Separate tests cover Activity reuse, immediate approval, owner isolation, missing credentials, and absence of control credentials from persisted Cluster messages and replies. A separate test kills an owned runner process with SIGKILL and restarts it against the same SQLite file: a pending approval resumes, and a committed external mutation without a recorded result becomes unknown without another invocation. Cloudflare deployment and multiple runners require separate verification.

Code execution records the accepted method catalog, VM policy, and host-call outcomes in Domain. Settlement order is independent of invocation order, so a replay can preserve concurrent promise completion order. `ExecuteCodeLive` runs a fresh QuickJS context for each replay attempt, executes approved host calls through native Activities, and wakes from native state streams while calls remain active. Tests cover continuations of `Promise.race` before an earlier call completes, rejection handling, replay, approval, cancellation, and uncertain mutations. The VM enforces the accepted memory, stack, segment, job, and JSON/log budgets and exposes no host process or network. Native host results can carry `Prompt.ToolModelOutputPart` text and files outside the guest JSON value. Code returns that content to the model only when the guest returns the exact original host object and its JSON remains unchanged. Copies, independent equal values, primitives and undefined retain ordinary JSON; native QuickJS object identity selects the originating call. Native file codecs retain bytes, and metadata counts toward the result budget. `RunCode` owns admission and top-level native compensation; `execute` in the default agent calls it as a linked native child before Code admission can commit. Parent and Code cancellation wake native state watches even during approval waits. Domain expiry and accepted cancellation facts drive scoped native controls.


`delegate` starts another run of the configured actor with a derived lineage and its own bounded tool allowance. The accepted Domain reservation supplies actor, prompt, identity and limits; guest JavaScript cannot supply execution authority. `RunDelegation` registers native admission compensation before committing the reservation, and `ExecuteDelegation` owns the child fence and terminal receipt. A process completing cleanup does not imply the child succeeded; the Domain status and receipt determine the result.

`DEFAULT_CODE_LIMITS` and `DEFAULT_DELEGATION_LIMITS` expose the reference policy defaults. Optional JSON settings `TARDIGRADE_CODE_LIMITS` and `TARDIGRADE_DELEGATION_LIMITS` supply a complete replacement policy; accepted executions retain their policy and method catalog across replay. The default subagent uses the same configured actor. Applications exposing multiple actors provide an allowlisted planner and matching native external-system implementation.

The default-agent integration tests use the real OpenAI Responses adapter over a local HTTP fixture. They exercise `RequestRun` through native policies, provider requests, Code Mode or delegation, tool execution, durable receipts and final parent completion. They do not make paid provider calls or prove Cloudflare deployment. The workspace chat CLI consumes the remote native API for admission, event cursors, directory pagination and terminal receipts. Workspace adapters, remaining apps, graph and deferred consumers still require cutover.

The named-text workspace is a Domain aggregate scoped to the immutable owner and thread. Tools validate the actual parent run before accessing it. Writes retain their original operation payload and receipt, so retrying an earlier write does not undo a later overwrite; reusing its operation ID with different text is refused. Native command IDs also bind the payload. Reads slice by character offset, and key listings use an exclusive lexical cursor. Empty keys and text remain valid.

`DEFAULT_WORKSPACE_POLICY` exports read/list allowances, current storage limits and write-receipt limits. `TARDIGRADE_WORKSPACE_POLICY` supplies a complete JSON replacement when a workspace is first opened. Existing workspaces retain their accepted policy across runner configuration changes. New writes fail when receipt retention is full, preserving idempotency evidence. The native aggregate read currently transfers the whole bounded workspace to the trusted runner before the domain read/list policy selects the response. This context stores named text. Complete result references use SpillCatalog and the separate SQL backend described below; uploaded blob storage and filesystem containment still require migration.

## Complete result references

The default agent freezes `TARDIGRADE_SPILL_POLICY` with each accepted Code execution. `DEFAULT_SPILL_POLICY` exports the complete policy: the byte threshold and preview allowance, read/context/match allowances, and value/count/total-storage limits. A thread with an existing native SpillCatalog retains its accepted policy. Code requires both `workspace.read` and `workspace.grep` in its frozen catalog before spill is enabled, so a result reference names actual capabilities.

A returned JSON value above the accepted threshold leaves a `{tmp,size,preview,note}` reference in the model context. The full bounded Code outcome remains available in CodeExecution; native SQL KeyValueStore persists the complete serialized value separately. The pointer reports the accepted read and search allowances. `workspace.read({ref,offset,length})` slices it by character offset, and `workspace.grep({pattern,ref})` searches complete stored values with bounded surrounding context and explicit match truncation. Direct model tools expose the same operations as `read_spill` and `grep_spills`. Owner/thread scope is supplied by trusted orchestration, and reads require the current authorized run. A later run of that thread can reuse the reference.

SpillCatalog records metadata and reserves immutable reference, digest and storage allowance before the SQL write; confirmation follows the write. Pending reservations count toward the limit. An exact retry recovers an interrupted reservation or verifies an already stored value, and a conflicting reference cannot overwrite it. Reads verify the complete value against its size and digest. Missing or corrupted confirmed values fail explicitly; retry does not repair them silently. Native Schema-backed string storage preserves BOM and Unicode, and malformed text is refused before reservation. No external KV manifest is maintained.

Known archive-capacity refusals produce a model-visible tool failure with the source execution ID and policy; they do not turn a known completed Code call into an uncertain external mutation. Transport or storage failures preserve their original cause and retain the run uncertainty when necessary. Code VM result/memory limits remain independent of the spill threshold: this path does not permit an unbounded result through the VM. Uploaded file/blob storage, workspace SQL and remaining RLM consumer contracts still need their own cutovers. SQL is not advertised by the default workspace catalog.


## Context and structured results

A thread may accept a `context` policy in its run limits. The exported `DEFAULT_CONTEXT_POLICY` declares character thresholds, retained context and summary size/output-token limits. Domain prepares and settles compaction steps; native Activities invoke the configured model. The original task, existing system messages and complete tool exchanges are preserved. Summaries remain assistant data. Actual summary usage counts against the existing budgets; cancellation or expiry prevents replacement while a returned paid result still records its usage, including after a successor run starts.

`RequestRun` accepts an optional `output` declaration containing a name and a closed JSON object schema. The chat CLI exposes the same declaration through `--output`. The native OpenAI adapter carries the schema alongside tools; Domain validates the final JSON once and persists the decoded result in the run receipt. An invalid result fails with `output_validation_failed` without a correction call. The nine supported string formats are asserted through native Schema filters; time and date-time require a valid RFC 3339 offset; unknown names are rejected at admission. The dependency patch and generated project manifest carry the importer hook. The selected provider model must support strict structured responses with tools.

## Inbox example

`packages/examples/agents/inbox.ts` defines a separate native Domain model for ordered text messages. `OpenInbox` accepts the storage and message limits, and `PostInboxMessage` returns the accepted text. A repeated message ID returns its original reply; conflicting payloads and other callers are rejected, including transport receipt replay. This context does not need an AI provider or an agent workflow.

From `packages/examples`, `bun run cloudflare` starts its Alchemy stack. Configure `TARDIGRADE_TOKEN` and `TARDIGRADE_SUBJECT` for the shared authenticated session boundary. The Worker hosts `InboxApi` through Domain Durable Objects. Its stack is independent of the agent stack; persisted data in another hosting stack requires an explicit import before cutover.


## Greeter example

`packages/examples/act.ts` runs a separate authenticated Domain Greeting model. Its policy starts the native Effect workflow after admission and interrupts it after cancellation. The handler is a Domain external system; settled results and failures return through Domain commands. The example provides `WorkflowEngine.layerMemory` after `Domain.InMemory` so native workflow interruption releases an active handler. This example is ephemeral and does not establish SQL or cloud recovery.

Run it with `TARDIGRADE_TOKEN` and `TARDIGRADE_SUBJECT`. `TARDIGRADE_GREETING_NAME` overrides the greeting name; `TARDIGRADE_GREETER_POLL_INTERVAL_MS` and `TARDIGRADE_GREETER_MAX_POLLS` override the exported positive polling defaults.


## Meeseeks Bun example

`packages/examples/bun.ts` is an authenticated native Domain client. Its model and execution stay in the native state server and Cluster runner described above. The request carries user text and explicit run limits, with native context compaction enabled by the exported default. The runner adapter owns system instructions and applies them once per inference; this client never inserts them into conversation history. Fetch and durable text workspace tools are provided by the configured runner. The example creates no local journal, scheduler or model-service catalog.

Set `TARDIGRADE_URL`, `TARDIGRADE_TOKEN`, `TARDIGRADE_THREAD_ID`, `TARDIGRADE_RUN_ID`, `TARDIGRADE_ACTOR`, `TARDIGRADE_INSTANCE`, `TARDIGRADE_THREAD_NAME` and `TARDIGRADE_MESSAGE`, then run `bun run bun` from `packages/examples`. Retry with the same thread ID, run ID and request to reuse the durable receipt. `TARDIGRADE_RUN_LIMITS` overrides the complete limit defaults. Configure `TARDIGRADE_INSTRUCTIONS` in the runner process, using the exported `DEFAULT_MEESEEKS_INSTRUCTIONS` for the concise assistant preset; restart the runner to change its instructions. The native owner commands in the generated CLI handle approval and cancellation while this client waits for a terminal receipt. Existing experimental local journals require an explicit import; this client does not read them. System messages already persisted by older clients remain historical data and require an explicit history migration before replacing their instructions.


## Counter quickstart

`tdg init counter --template quickstart` creates an authenticated native Domain Counter. Increment and Decrement reply with the resulting count. A committed-event policy starts a native Effect notification workflow for positive even counts. The Cloudflare platform owns durable state and workflow checkpoints; `dev:memory` is explicitly ephemeral. The generated CLI comes directly from CounterApi. It does not use the legacy method HTTP protocol or local atom journal. See the [introduction](/docs/welcome) for commands and cutover limits.
