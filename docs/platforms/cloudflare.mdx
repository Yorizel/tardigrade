Each actor instance has an `ActorDO` with its supervisor database. Each thread has a separate `ThreadDO` with its own SQLite database, runtime, checkpoint, and recovery alarm. Bun uses the same database boundaries with SQLite files. The Worker routes an instance ID to its directory, which forwards thread requests to their owning objects:

```ts title="worker.ts"
import { actorContext } from "tardie/agent"
import { createActorWorker } from "tardie/platform/cloudflare"
import definition from "./actor"
import { services } from "./services"

const worker = createActorWorker({
  actor: definition,
  actorContext,
  services: () => services(),
})
export const ActorDO = worker.ActorObject
export const ThreadDO = worker.ThreadObject
export default worker
```

`services` comes from the generated `services.ts` and supplies model and tool implementations. `actorContext` selects the services visible to agent setup. `createActorWorker` supplies the Worker router, `ActorObject` directory class, and `ThreadObject` runtime class. Export both classes and bind both namespaces. `createActorObject` and `createThreadObject` supply the classes separately for custom Worker routing. Thread object names encode the full actor, instance, and thread coordinate through `cloudflareThreadName`.

## Configure

`tdg init` generates `alchemy.run.ts`, `worker.ts`, and `tardigrade.json`. The stack declares the Worker, binds `ACTORS` to `ActorDO` and `THREADS` to `ThreadDO`, and lets Alchemy own their SQLite namespace migrations. Agent projects also declare the workspace container image and its `SANDBOX` namespace. RLM projects declare the model catalog D1 database with its migrations and the Worker Loader binding.

Model connections belong to `tardigrade.json`; model metadata belongs to `models.lock.json`. `tdg setup` updates those settings and saves prompted credentials to `.env` with mode 0600. Alchemy reads `.env` and the process environment, then binds each configured provider credential with native `Config.Redacted`. Set `TARDIGRADE_TOKEN` in the environment to require a bearer token on actor routes.

The stack uses `Alchemy.localState()`. Keep its `.alchemy` directory between deployments of a stage. An existing Wrangler deployment requires an explicit ownership and data migration before adopting this stack; generating a project does not transfer existing namespaces.

## Verify locally

Start with a project from the [Build an agent guide](/docs/build-an-agent):

```bash
bun run dev:cloudflare
```

Use the URL printed by Alchemy when allocating and calling a thread. `/healthz` is public. When authentication is enabled, export the same `TARDIGRADE_TOKEN` in the calling shell; reading `.env` for the Worker does not export its values to other shells.

```bash
curl "$ACTOR_URL/healthz"
tdg thread create --name quickstart --url "$ACTOR_URL"
tdg call message '{"text":"What is the weather in Singapore?"}' --thread quickstart --url "$ACTOR_URL"
```

## Deploy

The Alchemy CLI and Cloudflare provider are direct dependencies of generated projects. Authenticate through an Alchemy profile, inspect the plan, and deploy the same stage:

```bash
bun run plan:cloudflare --stage prod
bun run deploy:cloudflare --stage prod
```

The deployed Worker exposes the same thread creation, method invocation, cancellation, and event routes used during local development. `bun run destroy:cloudflare --stage prod` removes that stage's resources, including its actor data.

Independent routing requires directory entries with independent placement. Colocated journals require an explicit data migration before these factories can route them.

## Recovery

The host commits a watchdog record and an immediate alarm with journal admission, then awaits `storage.sync()` before acknowledging the commit or starting execution. The directory and each thread handle their own `alarm()`. A thread alarm restores that thread from its own database; it does not drive sibling runtimes. Each recovery attempt commits its counters and replacement alarm, then synchronizes storage before driving the runtime.

Effect and promise settlements advance the progress cursor and reset consecutive failures. Settled runtimes clear their wake; remote promises park until their recorded deadline. Terminal failures and exhausted budgets retain a blocked record and clear the wake. New messages preserve the block.

Configure recovery at Worker construction:

```ts
createActorWorker({
  // actor, services, actorContext
  watchdog: {
    policy: {
      attemptTimeoutMs: 30_000,
      keepAliveIntervalMs: 30_000,
      retryIntervalMs: 1_000,
      maxRetryIntervalMs: 30_000,
      maxAttempts: 20,
      maxNoProgressAttempts: 5,
    },
  },
  promises: { timeoutMs: 60_000, pollIntervalMs: 1_000 },
})
```

`DEFAULT_WATCHDOG_POLICY` and `DEFAULT_PROMISE_POLICY` are exported from `tardie/core`. The watchdog retries typed failures by default; defects and `WatchdogTerminalError` block recovery. Supply `watchdog.retryable(error)` to classify application failures. Promise expiry records `PromiseTimedOut` without requesting backend cancellation. A scheduled clock receives its timeout budget after its scheduled time. Configure a dedicated promise resolver's observation cadence with `createCloudflarePromiseResolver({ policy: { pollIntervalMs }, ... })`; the host supplies each recorded absolute deadline.

### Interpreter versions

Supply `version(env)` to identify the interpreter running an actor. Cloudflare exposes its Worker version ID through a version metadata binding:

```json
{
  "version_metadata": { "binding": "CF_VERSION_METADATA" }
}
```

```ts
type Env = { CF_VERSION_METADATA: { id: string } }

createActorWorker({
  // actor, services, actorContext
  version: (env: Env) => env.CF_VERSION_METADATA.id,
})
```

`ThreadCreated.version` records the creation version. On activation under a different version, the host appends `ThreadUpdated { version }` before decoding actor-defined events. The creation record and existing journal prefix remain immutable. When unfinished effects are retained, the framework logs a warning before resuming them under the new version, including the thread, previous version, new version, and pending effect count. Changes with no pending effects and same-version restarts stay quiet. Version identifiers are opaque strings; a rollback is also a version change. Omit `version` to leave version adoption disabled.

A watchdog receives a fresh budget when its recorded `recoveryVersion` differs from the supplied version, including when the record has no version. The version event, budget reset, fence increment, and immediate wake commit together. Same-version activations preserve the block. Pending work also receives the fresh budget and fence. The directory watchdog also adopts the supplied version on activation. A watchdog instance adopts its configured version on its first successful restore; later alarms reschedule without adopting again. A deployment takes effect when an object next activates; it does not wake dormant objects by itself.

Custom hosts restore the watchdog after loading durable records and before accepting work. Hosts serialize interpreter replacement and finish invalidating the old runtime before starting the replacement; fencing rejects late probes and outcomes, but cannot undo invalidation already in progress. Omitting the version disables adoption while allowing pending work to recover.

Version adoption permits another recovery attempt; it does not establish journal or effect-input compatibility. Actor schemas must decode the recorded history, and reconstructed pending effects must still satisfy the runtime's input verification. The Quint model `packages/platform/quint/interpreterVersion.qnt` checks budget bounds, wake coverage, rollback epochs, and stale-attempt fencing within its finite abstraction.

Background library methods can override the host's promise timeout. The override is recorded as an absolute deadline when the handle is accepted; replay retains that deadline.

```ts
import { Schema } from "effect"
import { Rpc } from "effect/rpc"
import { MethodExecution, MethodPromiseTimeout } from "tardie/libraries"

const research = Rpc.make("research", {
  payload: Schema.Struct({ question: Schema.String }),
  success: Schema.String,
  error: Schema.String,
})
  .annotate(MethodExecution, "background")
  .annotate(MethodPromiseTimeout, 300_000)
```

The host keeps live local fibres active with alarm heartbeats at `keepAliveIntervalMs`. Alarm handlers return while recovery runs. Heartbeats preserve the promise deadline and recovery counters; completion releases the wake, and a process crash returns to budgeted recovery. Remote promises park without keeping the local fibre alive. `modelServices({ timeoutMs })` uses the configured model timeout for inference promises too.

Local promise recovery reruns the originating act with its recorded reference and deadline. The act must recreate its producer and tolerate repeated execution; external operations must deduplicate by the reference. Cloudflare's finite alarm redeliveries leave a coverage gap if repeated crashes occur before the replacement alarm becomes durable.
