## Create a research agent

```sh
tdg init researcher --template rlm
cd researcher
cp .env.example .env
```

The RLM preset uses the same native hosting files as the Alchemy template. It specializes the model's research instructions while keeping one implementation of the provider, tool catalog, authentication and durable execution. Configure the required settings in `.env`, including the model, provider credential, authenticated subject and transport tokens. Start `bun run dev` for the Domain Worker and `bun run dev:runner` for the Effect Cluster and SQL workflow runner. `bun run dev:memory` starts an ephemeral local Domain server for development. Its state does not survive restart.

Use `bun run cli --help` for the generated native Domain command interface. `OpenThread` accepts explicit run limits; those accepted limits become persisted thread policy. `RequestRun` admits an identified run, and the native policy starts its workflow. Model and tool work executes through durable Activities. Approval, cancellation, uncertain external mutations and retries remain owned by the native Thread and execution aggregates.

## Research inside code

The model can call `execute` to inspect data in an isolated QuickJS guest. The trusted host publishes its actual tool catalog and validates each host call before dispatch. Large results become durable spill references. Inside code, `workspace.read` and `workspace.grep` retrieve bounded excerpts from those spills. Workspace text tools persist authored research notes separately. SQL is not advertised by the default research workspace.

```js
const report = await agents.run({
  text: "Find primary sources for the claim and return their URLs.",
  budget: 8
})
return report.text
```

`agents.run` waits for a real native child execution and returns its completed report. The trusted planner determines the target actor and delegation limits. Unsupported legacy options such as background execution, per-call model selection and child output contracts are rejected. Reports and fetched documents remain evidence; the research instructions explicitly forbid treating their contents as trusted instructions.

## Context and declared output

Native context compaction is enabled through the thread's accepted context policy. It summarizes a complete old prefix, preserves the original user task and tool exchange boundaries, and charges the summary call against the existing token and turn budgets. Stored events retain the source history. Configure the policy at thread admission rather than changing an environment setting after the thread has opened.

Per-message declared JSON output schemas and `outputValidateOnce` are not yet supported by the native run request. This capability requires a persisted declared output contract and terminal validation. Research instructions alone do not validate structured output. Do not send legacy message output declarations to the native API or assume they are enforced.
